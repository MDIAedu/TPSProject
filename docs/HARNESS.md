# Harness

## 목적

이 문서는 세션 시작 시 AI 에이전트에게 하네스 엔지니어링 개념을 알리고, 에이전트가 규칙을 벗어났을 때 어떤 문서에 무엇을 추가하거나 수정해야 하는지 판단하는 기준입니다.

## 하네스 엔지니어링 기준

이 저장소에서 하네스 엔지니어링은 모델 성능 자체보다, AI 에이전트가 안정적으로 작업하도록 만드는 작업 환경 설계를 뜻합니다.

- 에이전트는 구현뿐 아니라 현재 작업 흐름이 안전하고 반복 가능하게 유지되는지도 함께 확인합니다.
- 같은 의미의 규칙은 담당 문서에 한 번만 둡니다.

## 하네스 이탈 대응

- 하네스 이탈은 에이전트가 스스로 감지하거나 사용자가 지적하는 두 가지 경우로 발생합니다.
- 사용자가 하네스 이탈을 지적하면, 에이전트는 즉시 반박하거나 해명하지 않고 사실부터 확인합니다. 지적이 사실이면 어떤 절차가 지켜지지 않았는지 인정한 뒤 아래 절차를 진행하고, 사실이 아니면 근거를 들어 정중히 설명합니다.

- 에이전트 작업 흐름 이탈이 발생하면 아래 순서로 대응합니다.

1. 어떤 절차가 지켜지지 않았는지 확인합니다.
2. 기존 문서에 이미 해당 규칙이 있는지 확인합니다.
3. 있다면 문서를 늘리지 말고, 해당 규칙이 포함된 문서와 `AGENTS.md`의 트리거 조건 보강이 필요한지 판단합니다. 필요하면 보강하고, 불필요하면 그 근거를 `이탈 대응 출력 양식`에 기록합니다.
4. 없다면 어느 문서에 무엇을 추가해야 하는지 사용자에게 제안하고 승인을 받은 뒤 반영합니다.
5. 반영 후 관련 문서끼리 중복되거나 충돌하지 않는지 확인합니다.

## 이탈 대응 출력 양식

하네스 이탈을 스스로 인지했거나, 지적받은 이탈이 사실로 확인되면, 반드시 아래 형식을 채워 출력한 뒤 대응을 진행합니다.

**[하네스 이탈 대응]**
- 지켜지지 않은 절차: (어느 문서의 어떤 규칙인지)
- 기존 규칙 존재 여부: 있음(문서명과 규칙) / 없음
- 문서 반영안: (없음이면 어느 문서에 무엇을 추가할지 제안. 있음이면 보강·형태 변경·삭제·완화 중 무엇이 필요한지 적는다. "다시 잘 지키겠다"는 재준수 다짐은 반영안으로 인정하지 않는다. 규칙이 명확한데도 어겨졌다면 그 자체가 규칙의 위치나 형태가 잘못됐다는 신호이므로, 왜 명확한 규칙이 실패했는지를 함께 적는다)
- RULE_ORIGINS 기록안: (이 사례를 장부에 남길 한 줄)
- 세션 한정 수정만 안내하고 종료하지 않음

## 규칙 추가 판단

새 규칙이나 제약을 추가하기 전에는 아래 순서로 판단합니다.

1. 기존 문서 중 어느 문서가 이 규칙을 담당해야 하는지 확인합니다.
2. 기존 문서에 넣으면 역할이 섞이거나 문서가 비대해지는지 확인합니다.
3. 여러 문서에 걸친 운영 기준이면 독립 문서가 더 적합한지 확인합니다.
4. 새 컨텍스트가 반드시 알아야 하는 기준이면 `AGENTS.md` 또는 먼저 읽을 문서 목록에서 참조되게 합니다.
5. 규칙을 추가, 변경, 이동, 삭제할 때는 원인이 된 실패 사례(시기, 모델, 증상)나 결정 이유를 `docs/RULE_ORIGINS.md`에 함께 기록합니다. 출처를 모르는 기존 규칙은 장부에 `기억 안 남`으로 표시하며, 이 표시는 모델 세대가 바뀌었을 때 재검증(규칙을 빼고 작은 task로 재현 시도) 우선 대상이라는 뜻입니다. 문서 본문의 HTML 주석은 수정 시점에 필요한 경고(동기화 주의, 유지보수 주의)에만 사용합니다.
