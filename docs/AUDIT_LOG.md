# Audit Log

## 목적

이 문서는 하네스 감사(문서 간 중복·충돌·정합성 점검)의 체크리스트와 이력을 보관합니다.

- 평소 작업에서는 읽지 않습니다. 사용자가 감사를 요청할 때만 참조합니다.
- 감사는 정기·자동 절차로 강제하지 않고, 사용자가 필요할 때 요청하여 진행합니다. 이 문서는 감사 방법과 이력을 보존해 매번 처음부터 시작하지 않게 하는 용도입니다.
- 감사에서 나온 규칙 변경은 `docs/HARNESS.md`의 절차와 `docs/RULE_ORIGINS.md` 기록을 따릅니다.

## 감사 체크리스트

### 규칙 품질
- 같은 의미의 규칙이 여러 문서에 있는가 (중복 → 담당 문서로 통합, 나머지는 포인터)
- 규칙끼리 모순되는가 (예: 한쪽은 절대형 금지, 다른 쪽은 조건형 승인)
- 규칙이 담당 문서에 있는가 (소유권 — 예: 이름 규칙은 배치(ARCHITECTURE)가 아니라 작성(STYLEGUIDE) 문제)
- 훈계형 규칙(강제 장치 없이 "정확하게 해라"류)이 새로 생기지 않았는가 (반복 무시되면 양식·체크리스트로 승격)
- 실패 사례가 없는 규칙이 쌓이지 않았는가 (삭제 후보 — 장부에 기록 후 제거)

### 구조 정합성
- 절차와 양식이 일치하는가 (예: 절차는 "항상 보강", 양식은 "반영 불필요 허용" 같은 모순)
- 문서 맵이 실제 파일 목록과 일치하는가 / 트리거가 문서 관할과 일치하는가
- 단계 번호 참조("1, 4, 8~10" 등)가 깨지지 않았는가
- 축소·조건부 경로가 필요한 단계를 빠뜨리지 않았는가 (예: 의심 기재(6) 후 정리(11) 누락)

### 기록 정합성
- 장부(RULE_ORIGINS)가 본문·사실과 일치하는가
- 장부에 행동 규칙이 숨어 있지 않은가 (장부는 이력만, 규칙은 운영 문서에)
- 완료 상태와 task 문서 체크박스가 일치하는가
- 이전 프로젝트의 기록이 이월되지 않았는가 (PLANS/LOGS/PENDING_ISSUES)

### 검증 방법
- 실프로젝트의 실제 기록(task 문서, 로그, 보류 의심)으로 개정 규칙을 대조했는가
- 규모가 크거나 판단이 갈리는 감사라면, 다른 모델에게 교차 리뷰를 받았는가 (선택 — 제안 → 상대 평가 → 출처·원칙 기준 판정 → 수렴. 간단한 감사에는 생략 가능)
- 리뷰 제안이 성장 사다리를 건너뛰지 않는가 (실패 없는 자동화 제안은 발동 조건과 함께 조건부 보류)

## 감사 이력

- 2026-07: 전체 하네스 문서 + 실프로젝트 2개(AIStudio, TpsWithAI) 대조 + Claude/Codex 교차 리뷰 3회 왕복.
  발견: 충돌 소지 1(범위·승인 절대형 vs 조건형), 중복 2(비밀값, 이름 규칙), 공백 2(차단됨 절차 부재 → 상태 자체 삭제, 기록 문서 초기화 규칙 부재), 경로 결함 2(멀티턴 12~14 누락, 조건부 6·7에 10 누락), 정합성 3(절차-양식 모순, 장부 내 행동 규칙, 장부 사실 오류).
  처리: 통합·포인터화, 이탈 대응 양식/단계 체크리스트 승격, 출처 주석 → RULE_ORIGINS 장부 이관, 자동화 제안 3건 조건부 보류.
  실사례 검증: 수동 작업/결과 확인 구분 기준(변경 vs 관찰)과 차단됨 삭제가 과거 프로젝트 기록으로 지지됨을 확인.
