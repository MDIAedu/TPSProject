# Style Guide

## 목적
이 문서는 AI 에이전트가 코드를 작성할 때 따라야 할 Unreal C++, Blueprint, 에셋, 주석 규칙의 기준입니다.

## 공통 원칙

- 처음 보는 사람도 읽을 수 있도록 과도한 난이도의 패턴은 피합니다.

## 이름 규칙

- 클래스, 함수, 파일, 자산 이름은 모두 역할이 드러나게 작성합니다.
- 현재 프로젝트에 기존 네이밍 규칙이 있으면 그 규칙을 우선합니다.

### Unreal 자산 이름

- 캐릭터 Blueprint와 AI 관련 Blueprint는 `BP_AssetName` 접두어를 우선 사용합니다.
- UI는 `WBP_AssetName`, 애니메이션 블루프린트는 `ABP_AssetName`을 우선 사용합니다.
- 맵은 `L_MapName` 같은 이름을 우선 사용합니다.

### C++ 파일 이름

- C++ 파일 이름은 클래스 이름과 같은 기본 이름을 사용하고, 헤더와 구현 파일은 같은 기본 이름의 `.h`, `.cpp` 쌍으로 유지합니다.
- Unreal 클래스 접두어 규칙은 클래스 선언에 따르고, 파일 이름은 접두어를 제외한 실제 클래스 이름 기준으로 맞춥니다.

예시:

- `AMyCharacter` -> `MyCharacter.h`, `MyCharacter.cpp`
- `UBossHealthComponent` -> `BossHealthComponent.h`, `BossHealthComponent.cpp`

## Unreal C++ 규칙

- 액터, 컴포넌트, 시스템, UI처럼 책임 단위가 보이게 코드를 구성합니다.
- 지금 task에 필요한 동작만 작성하고, 미래 확장을 가정한 추상화는 기본적으로 추가하지 않습니다.

## Blueprint 규칙

- Blueprint는 상태 흐름과 이벤트 연결이 읽히게 구성합니다.
- 하나의 Blueprint에 여러 unrelated 시스템을 몰아넣지 않습니다.
- 현재 task 범위에서 필요한 입력, 상태 변화, 사용자 반응만 노출합니다.

## Unreal Editor 작업 규칙

- Unreal Editor에서 일반적으로 생성·설정하는 에셋과 설정은 사용자가 명시적으로 요청하지 않는 한 코드로 대체 생성하지 않는다.
- 해당 자산이 필요하면 사람이 에디터에서 직접 만드는 전제로 작업합니다.
- 맵이나 다른 자산에서 직접 배치해서 사용하는 대상은, 사용자의 별도 요청이 없으면 C++ 클래스를 바로 배치 대상으로 삼기보다 Blueprint 등 에디터 자산으로 만들어 사용한다.
- 에디터에서 선택·배치·연결하는 대상은, 사용자의 별도 요청이 없으면 코드에서 구체 대상으로 확정하거나 기본값으로 자동 지정하지 않고 기본적으로 에디터에서 설정 가능하게 둔다.


## 에셋 규칙

- 임시 에셋과 최종 에셋은 구분 가능하게 관리합니다.
- 모델, 애니메이션, UI 자산은 현재 task에서 필요한 상태 구분과 사용자 인지를 지원해야 합니다.

## 주석 규칙

- 초보자 기준으로 이해를 돕는 주석은 허용합니다.
- 주석은 기본적으로 한글로 작성합니다.
- 왜 이런 분기나 상태 처리가 필요한지처럼 코드만으로 바로 드러나지 않는 맥락을 우선 기록합니다.
- 함수에는 어떤 기능을 하는 함수인지 꼭 주석을 작성합니다.

## 금지 또는 제한 규칙

- 플러그인, 모듈, 시스템 도입 같은 task 범위 밖 작업의 금지와 승인 절차는 `docs/WORKFLOW.md`의 `진행 제약`을 따릅니다.
- 비밀값 취급 규칙은 `docs/WORKFLOW.md`의 `진행 제약`을 따릅니다.
- “나중에 쓸 수도 있다”는 이유만으로 미사용 상태, 더미 데이터 구조, 가짜 설정 항목을 추가하지 않습니다.
