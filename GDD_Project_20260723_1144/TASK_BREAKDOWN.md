# Task Breakdown — 실험실 회피 사격 보스전

이 문서는 `GDD_Project_20260723_1144/Game_GDD.md` 기획을 바이브 코딩으로 단계별 구현하기 위한 task 목록입니다.

- 각 task는 `Tasks/MAKE_REQUEST_TEMPLATE.md` 형식에서 `# 사용자 요청`을 생략한 `## 원하는 동작` + `## 세부 설명`으로 작성했습니다.
- 위에서부터 순서대로 하나씩 요청해 진행하는 것을 전제로 나눴습니다. 각 task는 한 번에 하나의 동작만 검증할 수 있도록 최소 단위로 쪼갰습니다.
- GDD 방식(`큐브 기반 동작 검증 후 모델과 붙이는`)에 따라 초반 task는 큐브/캡슐 임시 형상으로 동작을 검증하고, 실제 모델·에셋은 4주차(`04-1`)에 교체합니다.
- 세부 설명의 수치는 GDD `5. 규칙과 목표`의 확정값이며, 모두 나중에 쉽게 수정 가능한 조정값으로 둡니다.
- 실제 `docs/PLANS.md` 단계 추가와 개별 task 파일 생성은, 각 task를 실제로 요청해 진행 시작하는 시점에 만듭니다. (이 문서는 요청 목록/순서 정의용입니다.)

## 1주차 — 기반, 이동, 카메라, 기본 사격

### Task 01-1 — 프로젝트 세팅과 실험실 맵

#### 원하는 동작
- 사각형 실험실 전투 공간과 플레이어 시작 지점이 있는 기본 플레이 맵을 만든다.

#### 세부 설명
- 장애물 없이 평평한 중간 크기 사각형 전투 공간 1개로 구성한다.
- 플레이어는 실험실 한쪽 끝, 보스 자리는 중앙 또는 반대편으로 시작 위치만 배치한다. (보스 로직은 이후 task)
- 이 시점 플레이어/보스는 임시 큐브 또는 캡슐 형상으로 배치한다.
- SF 실험실 분위기는 이후 단계에서 다루고, 지금은 동작 검증용 기본 형상만 둔다.

### Task 01-2 — 플레이어 TPS 이동

#### 원하는 동작
- 플레이어 큐브가 키보드 WASD 입력으로 실험실 안을 이동한다.

#### 세부 설명
- 이동 입력은 WASD를 사용한다.
- 이 시점에는 카메라 기준 방향 이동이 아니어도 되며, 큐브가 입력대로 움직이는 것만 검증한다.
- 실제 캐릭터 모델은 아직 붙이지 않는다.
- Enhanced Input 을 이용해.
- AChracter 클래스를 이용해.

### Task 01-3 — 3인칭 숄더뷰 카메라

#### 원하는 동작
- 마우스로 조작하는 3인칭 숄더뷰 TPS 카메라를 붙인다.

#### 세부 설명
- 카메라는 일반적인 3인칭 숄더뷰(어깨 너머 시점)로 플레이어를 따라간다.
- 마우스로 시점을 회전할 수 있다.
- 카메라 기준 방향으로 이동이 동작하도록 이동과 연동한다.

### Task 01-4 — 조준과 기본 사격

#### 원하는 동작
- 마우스 우클릭으로 조준하고 좌클릭으로 정면에 기본 사격을 한다.

#### 세부 설명
- 우클릭(또는 기본 TPS 조준 방식)으로 조준 상태에 들어간다.
- 좌클릭으로 사격하며, 탄이 나가는 방향/피격 판정을 큐브 대상으로 검증할 수 있게 한다.
- 이 시점 피해량·콤보·탄창은 다루지 않고, 사격 발생과 명중 판정만 확인한다.

## 2주차 — 회피, 콤보, 탄창, 보스

### Task 02-1 — 대쉬/구르기 회피

#### 원하는 동작
- Space 또는 Shift 입력으로 대쉬/구르기 회피를 하고 쿨타임이 적용된다.

#### 세부 설명
- 회피 입력은 Space 또는 Shift로 한다.
- 회피 쿨타임 기본값은 1.2초이며 조정 가능한 값으로 둔다.
- 쿨타임 중에는 재회피가 되지 않아야 한다. (쿨타임 잔여 표시는 HUD task에서 다룸)

### Task 02-2 — 3단 콤보 사격

#### 원하는 동작
- 연속 사격이 1타·2타·3타로 이어지는 3단 콤보로 동작한다.

#### 세부 설명
- 콤보 단계별 피해량 기본값은 1타 10, 2타 15, 3타 25이며 조정 가능한 값으로 둔다.
- 콤보가 끊기는 조건(입력 간격 등)을 두고, 현재 콤보 단계를 내부적으로 관리한다.
- 콤보 단계 값은 이후 HUD에서 표시할 수 있도록 참조 가능하게 둔다.

### Task 02-3 — 재장전과 탄창

#### 원하는 동작
- R 키로 재장전하고 현재 총알 수와 최대 탄창 수가 관리된다.

#### 세부 설명
- 사격 시 총알이 줄고, R 키로 재장전한다.
- 총알이 0이면 재장전 전까지 사격되지 않는다.
- 탄창 기본값은 구현 중 조정하며, 현재/최대 탄창 값을 이후 HUD에서 표시할 수 있게 둔다.

### Task 02-4 — 보스 추적

#### 원하는 동작
- 보스 큐브가 플레이어를 추적해 이동한다.

#### 세부 설명
- 보스는 임시 큐브/캡슐 형상으로 플레이어 위치를 향해 추적 이동한다.
- 이 시점 공격·체력은 다루지 않고 추적 이동만 검증한다.

### Task 02-4 추가 — 보스 횡이동
## 원하는 동작

- 보스 큐브가 플레이어를 주시한 상태로 주위를 이동한다.

## 세부 설명

- 현재 보스는 플레이어를 향해 단순히 추적 이동만 한다.
- 이동 중 일정 확률로 추적 대신, 플레이어를 계속 바라보면서 주위를 도는 횡이동으로 전환되게 하고 싶다.
- 횡이동 중에도 보스는 항상 플레이어 쪽을 바라봐야 한다.
- 앞으로 보스 이동/행동 상태가 계속 추가될 예정이므로, 상태 전환은 FSM(유한 상태 기계) 구조로 설계한다.


### Task 02-5 — 보스 공격 패턴 (일반 공격)

#### 원하는 동작
- 보스가 근접 거리에서 일반 공격으로 플레이어를 공격한다.

#### 세부 설명
- 기존 추적/횡이동 FSM에 공격 상태를 추가한다.
- 보스와 플레이어 거리가 근접 사거리 이하가 되면 일반 공격 상태로 전환된다.
- 기본 피해량은 20이며, 사거리·재사용 대기시간(쿨타임)은 조정 가능한 값으로 둔다.
- 공격 재사용 대기시간은 플레이어가 회피로 피할 수 있는 타이밍이 되도록 조정한다.
- 공격이 끝나면 보스가 다시 추적 상태로 돌아간다.

### Task 02-6 — 보스 공격 패턴 (점프 내려찍기)

#### 원하는 동작
- 보스가 플레이어와 거리가 있을 때 플레이어 앞까지 점프해 내려찍는 공격을 한다.

#### 세부 설명
- 플레이어와의 거리가 근접 사거리보다 멀 때 점프 내려찍기 상태로 전환되는 분기를 추가한다.
- 발동 시점의 플레이어 위치를 착지 지점으로 고정하고 그 지점으로 점프한 뒤, 착지 시 그 지점을 중심으로 한 원형 범위 공격으로 판정한다.
- 착지 지점은 점프 도중 갱신하지 않아, 플레이어가 착지 전에 범위를 벗어나면 피해를 받지 않는다.
- 기본 피해량은 20이며, 발동 거리, 점프 소요 시간, 판정 범위, 재사용 대기시간(쿨타임)은 조정 가능한 값으로 둔다.
- 공격이 끝나면 보스가 다시 추적 상태로 돌아간다.

## 3주차 — 체력, 승패, HUD, 화면

### Task 03-1 — 플레이어 체력과 피격/사망

#### 원하는 동작
- 플레이어가 보스 공격에 피격되어 체력이 줄고 0이 되면 사망 처리된다.

#### 세부 설명
- 플레이어 체력 기본값은 100이며 조정 가능한 값으로 둔다.
- 보스 공격에 맞으면 피해량만큼 체력이 감소한다.
- 체력이 0이 되면 사망 상태로 전환한다. (패배 화면 연결은 03-3에서)

### Task 03-2 — 보스 체력과 피격

#### 원하는 동작
- 보스가 플레이어 사격에 피격되어 체력이 줄고 0이 되면 처치 처리된다.

#### 세부 설명
- 보스 체력 기본값은 300이며 조정 가능한 값으로 둔다.
- 콤보 단계별 피해량이 보스 체력에 반영된다.
- 체력이 0이 되면 처치 상태로 전환한다. (승리 화면 연결은 03-3에서)

### Task 03-3 — 승리/패배 흐름

#### 원하는 동작
- 보스 처치 시 승리, 플레이어 사망 시 패배로 전투가 종료된다.

#### 세부 설명
- 보스 체력 0 → 승리, 플레이어 체력 0 → 패배로 판정한다.
- 별도 탈출 지점 없이 승리/패배 결과 상태로 전환한다.
- 결과 화면 자체 UI는 03-5에서 붙이고, 여기서는 판정과 전투 종료 흐름을 검증한다.

### Task 03-4 — 전투 HUD

#### 원하는 동작
- 플레이어 체력, 보스 체력, 회피 쿨타임, 콤보 단계, 탄창을 표시하는 HUD를 붙인다.

#### 세부 설명
- 표시 항목: 플레이어 체력, 보스 체력, 대쉬/구르기 쿨타임, 콤보 단계, 총알 개수/최대 탄창.
- 각 값은 실제 게임 상태와 실시간으로 일치해야 한다.
- 가독성을 우선하고, 최소한의 조작 안내만 둔다.

### Task 03-5 — 시작 화면과 결과 화면

#### 원하는 동작
- 게임 시작 화면과 승리/패배 결과 화면(다시 시작 안내)을 붙인다.

#### 세부 설명
- 시작 화면: 게임 시작 버튼 또는 바로 전투 시작.
- 결과 화면: 승리 시 보스 처치 문구, 패배 시 플레이어 사망 문구, 다시 시작 안내.
- 전투가 처음부터 끝까지 화면 전환 포함해 끊기지 않고 진행되게 연결한다.

## 4주차 — 모델 교체, 사운드, 마감

### Task 04-1-1 — 플레이어 스켈레탈 메시와 기본 로코모션 적용

#### 원하는 동작
- 플레이어 큐브를 Paragon Wraith 스켈레탈 메시로 교체하고, 이동에 맞춰 기본 로코모션 애니메이션이 재생된다.

#### 세부 설명
- 스켈레탈 메시, 대기/이동 애니메이션 에셋은 준비되어 있다.
- 기존 `UStaticMeshComponent` 큐브를 제거하고, 스켈레탈 메시를 Character의 메시 컴포넌트에 연결한다.
- 이동 로코모션은 8방향 Blend Space로 새로 만들어서 사용한다.
- 대기, 정면, 후면, 좌, 우 애니메이션을 기준으로 8방향을 구성하며, 앞좌/앞우는 정면 애니메이션을, 뒤좌/뒤우는 후면 애니메이션을 그대로 재사용해 ±45도 방향 슬롯에 배치한다.
- 이동 입력·이동 속도에 맞춰 이 Blend Space가 재생되는 Animation Blueprint를 구성한다.
- 카메라, 사격, 회피, 재장전 등 기존 조작은 이번 task에서 다루지 않고, 모델 교체와 이동 애니메이션 동작만 검증한다.

### Task 04-1-2 — 공통 조준 자세(Aim Offset) 적용

#### 원하는 동작
- 일반 상태와 우클릭 조준 상태 모두에서 마우스 상하 움직임에 따라 캐릭터 상체가 정면, 위, 아래 방향을 자연스럽게 바라본다.

#### 세부 설명
- 일반 상태와 우클릭 조준 상태는 카메라 줌만 다르고 캐릭터 자세와 사격 모션은 동일하게 유지한다.
- 두 상태 모두 같은 Aim Offset 에셋을 같은 강도로 적용한다.
- 마우스 상하 입력 또는 카메라 Pitch 값을 Animation Blueprint로 전달해 Aim Offset의 세로 축 값으로 사용한다.
- 카메라가 수평에 가까우면 정면 조준 자세가 재생된다.
- 마우스를 위로 움직여 카메라가 위를 보면 상체가 위쪽 조준 자세로 블렌드된다.
- 마우스를 아래로 움직여 카메라가 아래를 보면 상체가 아래쪽 조준 자세로 블렌드된다.
- Aim Offset은 이동 로코모션과 충돌하지 않아야 한다.
- 이번 task에서는 정면/위/아래 자세 전환만 검증하고, 좌우 조준, 사격 몽타주, 탄 발사 판정 변경은 다루지 않는다.

### Task 04-1-3 — 사격 콤보 애니메이션 연동

## 원하는 동작
- 좌클릭 3단 콤보 사격에 맞춰 각 단계별 공격 애니메이션이 재생된다.
- 다음 콤보 입력 가능 여부는 단순 시간값이 아니라 애니메이션의 Anim Notify 구간을 기준으로 관리한다.

## 세부 설명
- 기존 3단 콤보 로직의 1타/2타/3타 단계에 맞춰 각각의 공격 몽타주 또는 몽타주 섹션을 재생한다.
- 각 콤보 애니메이션 후반부에 다음 콤보 입력을 받을 수 있는 Anim Notify를 둔다.
- 입력 허용 Notify 이전에 들어온 좌클릭은 다음 콤보로 전환하지 않는다.
- 입력 허용 구간 안에 좌클릭이 들어오면 즉시 다음 콤보 몽타주 또는 섹션으로 전환한다.
- 입력 허용 구간을 지나도록 추가 좌클릭이 없으면 현재 콤보는 종료되고, 다음 좌클릭은 기존 리셋 규칙에 따라 1타부터 시작한다.
- 3타 이후에는 다음 콤보로 전환하지 않고 콤보를 종료한다.
- 다음 공격으로 전환될 때 자연스럽게 보이도록 몽타주 Blend In/Blend Out 또는 섹션 전환 값을 조정한다.
- 기존 피해량, 명중 판정, 피해 적용 로직은 변경하지 않는다.


### Task 04-1-4 — 재장전 애니메이션 연동

#### 원하는 동작
- R 키 재장전 시 재장전 애니메이션이 재생되고, 애니메이션 재생 중 사격이 되지 않는다.

#### 세부 설명
- 사용 가능한 재장전 전용 애니메이션이 없으면 대체 애니메이션 사용 여부를 확인한 뒤 진행한다.
- 재장전 애니메이션이 끝나는 시점에 맞춰 현재 탄창 수가 최대치로 채워지도록, 기존 즉시 재장전 로직의 타이밍을 애니메이션 길이에 맞춘다.
- 재장전 애니메이션 재생 중에는 사격 입력이 무시되는지 확인한다.

### Task 04-1-5 — 회피(대쉬/구르기) 애니메이션 연동

#### 원하는 동작
- Space 또는 Shift 회피 입력 시 이동 방향에 맞는 회피/구르기 애니메이션이 재생된다.

#### 세부 설명
- 사용 가능한 회피 전용 애니메이션이 없으면 대체 애니메이션 사용 여부를 확인한 뒤 진행한다.
- 기존 회피 이동(런치) 지속 시간과 회피 애니메이션 재생 길이가 자연스럽게 맞물리는지 확인한다.
- 회피 애니메이션 재생 중에도 기존 쿨타임 로직은 그대로 유지된다.

### Task 04-1-6 — 보스·실험실 에셋 교체

#### 원하는 동작
- 보스 큐브와 실험실 임시 형상을 실제 보스 모델과 실험실 에셋으로 교체한다.

#### 세부 설명
- 기본 에셋, 무료 에셋, 임시 에셋 중심의 SF 실험실 분위기로 교체한다.
- 교체 후에도 보스 추적, 횡이동, 근접 공격, 점프 내려찍기 등 기존 동작이 그대로 유지되어야 한다.
- 최종 아트 완성도보다 전투 판정을 우선한다.

### Task 04-2 — 효과음

#### 원하는 동작
- 사격, 피격, 회피, 보스 공격 예고, 승리/패배에 효과음을 붙인다.

#### 세부 설명
- 필요한 사운드: 사격음, 피격음, 대쉬/구르기 효과음, 보스 공격 예고음, 승리/패배 효과음.
- 보스 공격 예고음은 회피 타이밍을 알 수 있게 공격 발생 전에 재생한다.
- 임시/무료 사운드 에셋을 사용해도 된다.

### Task 04-3 — 밸런싱, 버그 수정, 제출 빌드

#### 원하는 동작
- 난이도 수치를 조정하고 버그를 수정한 뒤 제출용 빌드를 준비한다.

#### 세부 설명
- 체력, 피해량, 쿨타임, 탄창 크기, 보스 공격 간격을 플레이 감각에 맞게 조정한다.
- 마감 전 점검: 전투가 처음부터 끝까지 끊기지 않는지, 승리/패배가 정상 작동하는지, HUD 수치가 실제 게임 상태와 맞는지 확인한다.
- 제출용 플레이 가능한 프로토타입 빌드를 준비한다.
